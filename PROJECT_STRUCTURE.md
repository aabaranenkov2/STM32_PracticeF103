# Структура проектов: STM32_Fitnes1 vs STM32_PracticeF103

## 🔍 Разница между проектами

### STM32_Fitnes1 (Основной проект)
**Назначение:** Полноценный фитнес-трекер для NUCLEO-G491RE

**Структура:**
```
STM32_Fitnes1/
├── src/              # Исходный код
│   ├── main.c
│   ├── algorithms/  # Алгоритмы (Health Score, Readiness Score)
│   ├── sensors/     # Драйверы датчиков (MAX30102, ADXL345, DS3231)
│   ├── communication/ # Bluetooth, SD карта, UART
│   └── ui/          # Дисплей
├── include/         # Заголовочные файлы (.h)
│   ├── algorithms/
│   ├── sensors/
│   ├── communication/
│   └── ui/
├── lib/             # Внешние библиотеки
└── test/            # Unit-тесты
```

**Почему есть lib, test, include:**
- ✅ **include/** - заголовочные файлы для модульной архитектуры
- ✅ **lib/** - внешние библиотеки (через PlatformIO или вручную)
- ✅ **test/** - unit-тесты для проверки алгоритмов

---

### STM32_PracticeF103 (Учебный проект)
**Назначение:** Простая практика на STM32F103C8T6 для отладки прошивки

**Текущая структура:**
```
STM32_PracticeF103/
├── src/
│   └── main.c       # Простой код мигания LED
└── platformio.ini
```

**Почему НЕТ lib, test, include:**
- ❌ **include/** - не нужен, весь код в одном файле `main.c`
- ❌ **lib/** - не используются внешние библиотеки
- ❌ **test/** - простой код не требует тестов

---

## 💡 Когда нужна структура как в STM32_Fitnes1?

### Нужна структура, если:
1. ✅ Код разбит на модули (датчики, алгоритмы, коммуникация)
2. ✅ Есть заголовочные файлы (.h) для разделения интерфейса и реализации
3. ✅ Используются внешние библиотеки
4. ✅ Нужны unit-тесты для проверки алгоритмов
5. ✅ Проект растет и нужна организация кода

### НЕ нужна структура, если:
1. ❌ Простой код в одном файле (как сейчас - мигание LED)
2. ❌ Нет модулей и разделения кода
3. ❌ Нет внешних библиотек
4. ❌ Нет необходимости в тестах

---

## 🚀 Создать структуру для STM32_PracticeF103?

Если вы хотите практиковаться с модульной архитектурой, можно создать аналогичную структуру:

```
STM32_PracticeF103/
├── src/
│   ├── main.c
│   ├── sensors/     # Драйверы датчиков (если подключите)
│   └── utils/       # Утилиты
├── include/
│   ├── sensors/
│   └── utils/
├── lib/             # Внешние библиотеки (если понадобятся)
└── test/            # Тесты (если будете писать)
```

## 📋 Рекомендация

**Для текущего проекта (STM32_PracticeF103):**
- Оставить простую структуру (только `src/main.c`)
- Это учебный проект для отладки прошивки
- Не усложнять без необходимости

**Когда переходить на модульную структуру:**
- Когда начнете подключать датчики (MAX30102, ADXL345)
- Когда код станет больше 200-300 строк
- Когда понадобятся заголовочные файлы для разделения кода
